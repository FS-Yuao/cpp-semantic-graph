## 项目目标

把 `docs/` 下 91 个散落 markdown 文档结构化成语义关联网络，让 Agent 在用户提问时能直接从图谱拿到答案，不再依赖 `grep` + `find` + `Read` 全局扫。

**核心理念**：与代码图谱一致——节点 + 边 + BFS 遍历，确定性、可解释、可追溯。不依赖 GPU 向量搜索。

## 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 文档图谱 vs 增强现有 cppsg | 独立文档图谱 | cppsg 文档系统实测效果差（LIKE 搜"AB分区方案"=0结果） |
| 搜索技术 | FTS5 + BM25 | 91 文档量级不需要 GPU；FTS5 只负责找起始节点 |
| 融合方式 | 符号桥接 + BFS | 文档和代码的关联点是符号名，精确匹配即可 |
| 是否用 GraphRAG | 自研 | 文档是半结构化的，规则解析比 LLM 提取更准；融合层无人能替 |
| 查询模式 | 纯图结构遍历 | 与代码图谱一致，确定性、可解释 |
